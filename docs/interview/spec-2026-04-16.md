# Spec — jaewon-plugin-learning (v0.1)

Derived from interview 2026-04-16. This is the input the Planner will expand into a phased implementation plan.

## 1. Mission

A Claude Code plugin that teaches one learning material at a time (code repos, folders of notes, math/science articles), growing a persistent wiki and a learner profile so the main-session TEACHER gets sharper and more customized with every chapter.

## 2. Core Concepts

- **Course** — one input (a folder, a GitHub repo URL, or a curated raw-materials/ subfolder). Lives on its own git branch.
- **Chapter** — curriculum unit within a course. Each chapter runs one full cycle.
- **Cycle** (per chapter) — three phases in order:
  1. **Read** — teacher walks through materials with interactive QA. Wiki captures what was read + open questions.
  2. **Summarize** — learner writes own summary in the wiki. Teacher does not assist during drafting.
  3. **Discuss** — teacher runs sharp, strict, adaptive interrogation against the summary + materials. Ends with a verdict.
- **Verdict** — Incomplete | Partial | Mastery. Mastery merges the chapter branch; Partial loops cycle in same branch.
- **Wiki** — karpathy-style knowledge base. Content pages + learner-profile pages + index.md + log.md.
- **Learner profile** — `wiki/learner/` pages written/updated by profiler agent after every discuss phase. Includes learning-style, strengths, weaknesses, push-tactics, session-log.
- **Teacher** — the main Claude session. Adaptive voice selected per session from push-tactics.md. Delegates to sub-agents for prep/profiling/crawling/verification.

## 3. Plugin Architecture (target)

- **Plugin repo:** `jaewon-plugin-learning/` subfolder (this repo) — ships agents, skills, hooks, MCP server, CLAUDE.md for plugin.
- **Wiki template repo:** separate template (forkable) — ships wiki/ scaffold with SCHEMA.md, index.md, log.md, learner/, courses/, plus a CLAUDE.md that defines the learner-wiki workflow and references learner/ files.
- **User flow:** user forks template once → cd into fork → run plugin skills to ingest courses, each on its own branch.

## 4. GitHub Workflow

- `main` branch = canonical learned-material + profile snapshot.
- New course → new branch `course/<slug>`.
- Plugin commits per cycle phase (read, summarize, discuss, profiler update).
- Verdict = Mastery → auto-merge into main, push.
- Dashboard is regenerated on merge and committed to main (or published via GitHub Pages).

## 5. Agents (proposed roster — planner may adjust)

- **researcher** (haiku/sonnet) — aggressive crawler: WebSearch + WebFetch + GitHub search + arxiv + YouTube transcripts. Ingests widely for one chapter.
- **planner** (opus) — proposes chapter outline from material + crawl results.
- **critic** (opus) — reviews outline for scope, depth, dependency order.
- **creator** (sonnet) — drafts per-chapter read-phase pages in the wiki.
- **profiler** (sonnet) — after every discuss phase, updates wiki/learner/* pages with observations.
- **evaluator** (sonnet) — produces verdict from discuss transcript + summary + material.
- **wiki-maintainer** (sonnet) — maintains wiki integrity: index.md, log.md, cross-references, lint.
- **dashboard-builder** (haiku) — regenerates static HTML dashboard from wiki + profile.
- **git-manager** (haiku) — branch/commit/merge/push automation.

Teacher = the main session, not a separate agent. Main session orchestrates.

## 6. Skills (proposed — planner may adjust)

- **setup-learning-wiki** — fork or init the wiki template for this user.
- **new-course** — ingest a course (folder or GitHub URL), crawl, produce outline, user approves, create branch, scaffold chapters.
- **learn** — run the read→summarize→discuss cycle for the current chapter. Commits per phase.
- **resume** — resume active course/chapter/phase.
- **verdict** — end-of-discuss evaluation, writes verdict, triggers merge or cycle repeat.
- **wiki-lint** — integrity check of wiki pages + profile.
- **dashboard** — regenerate dashboard, optional publish.
- **profile-review** — present learner profile to user for manual editing if desired.

## 7. Hooks (proposed)

- `SessionStart` — load wiki/learner/* into context; set active branch/course/chapter state.
- `UserPromptSubmit` — nudge if user chats off-task during a learn cycle phase.
- `Stop` / `SubagentStop` — trigger profiler after discuss phase completes.
- `SessionEnd` — commit any pending phase work, update session-log.md.

## 8. MCP Tools (proposed)

- `learning_status` — read/write current course, chapter, cycle phase.
- `learning_profile` — read learner-profile pages (projection).
- `learning_wiki_search` — structured search over wiki pages.
- `learning_verdict` — record verdict + advance state.

## 9. Dashboard

Static HTML generator: homepage with courses list, per-course page with chapters + verdicts, profile page summarizing learner state, timeline view of sessions. Output to `dashboard/` in the wiki repo. Optional GitHub Pages publish flow.

## 10. Self-Improvement Mechanism

Every discuss phase →
1. Evaluator scores answer quality, identifies tactic used + learner engagement signal.
2. Profiler appends observation to `wiki/learner/session-log.md` and synthesizes updates into `learning-style.md`, `strengths.md`, `weaknesses.md`, `push-tactics.md`.
3. Next session: teacher reads `push-tactics.md` first, picks tactic, behaves accordingly.
4. CLAUDE.md never edited; it points to `wiki/learner/` as the source of truth.

## 11. Non-Goals for v0.1

- Multi-user support.
- Integration with Anki / spaced repetition.
- Voice/audio lessons.
- Real-time collaboration.

## 12. Success Criteria

- User can ingest one GitHub repo (e.g., a small transformer implementation) and run one full chapter cycle in under 30 minutes.
- Wiki after one chapter is human-readable, has working links, and contains a meaningful profile delta.
- Next chapter's teacher voice is observably different from the first (adaptation verified).
- All cycle phases auto-commit; merge-on-mastery works end-to-end.
- Dashboard renders course + profile after merge.
